# Shrimpl Risk Platform
## Data Schema Specification

Version: 1.0  
Purpose: Define the core data structures required by the Shrimpl risk modeling system.

This document specifies the datasets required for the biological, environmental, insurance, credit and stochastic models.

The system operates at **pond-level resolution**.

Primary data key:

pond_id + date

---

# 1. Pond Master Table

## pond_master

Defines the universe of ponds that the system models.

Each pond must have a stable identifier and spatial geometry.

### Fields

| Field | Type | Description |
|------|------|-------------|
| pond_id | string | Unique pond identifier |
| farm_id | string | Farm identifier |
| company_id | string | Company identifier |
| country | string | Country where the pond is located |
| system | string | Production system (extensive, semi-intensive, intensive, super-intensive) |
| area_ha | float | Pond area in hectares |
| centroid_lat | float | Pond centroid latitude |
| centroid_lon | float | Pond centroid longitude |
| geometry | polygon | Pond spatial polygon |
| active_from | date | Date pond started operation |
| active_to | date | Optional end date |
| source | string | Data source of pond geometry |

### Optional fields

| Field | Type | Description |
|------|------|-------------|
| species | string | Shrimp species |
| stocking_density | float | Stocking density (shrimp/m²) |
| watershed | string | Hydrological basin |
| region | string | Administrative region |

# 6. Data Pipeline Responsibilities

The following data must be produced by external pipelines.

### Satellite pipeline

Produces:

pond_wq_timeseries

Pipeline steps:

1. Satellite image ingestion
2. Water quality retrieval models
3. Pixel-level water quality estimation
4. Spatial intersection with pond polygons
5. Aggregation to pond statistics

---

### Climate pipeline

Produces:

pond_climate_timeseries

Pipeline steps:

1. Climate data ingestion (Copernicus CDS)
2. Raster extraction
3. Spatial intersection with pond centroids
4. Aggregation to daily values

---

# 7. Data Volume Expectations

System designed for:

- >1.5 million ponds
- >10 years of historical observations
- observation frequency: daily or every 3 days

Estimated rows:


pond_wq_timeseries

1.5M ponds
× 1200 observations
≈ 1.8 billion rows


---

# 8. Data Quality Requirements

Minimum acceptable conditions:


valid_pixel_fraction > 0.5
quality_score > 0.6


Observations below thresholds may be filtered or down-weighted.

---

# 9. Versioning

All pipelines should record:


processing_run_id
retrieval_model_version


to allow reproducibility.
